# ADC Nexus 课程演示部署

老师访问的是以 HTTPS 开头的公网课程演示地址。这个部署目录使用合成数据、六个公开演示岗位和单独的 PostgreSQL 数据卷。系统的收款与退款操作只登记演示用凭据。权限管理员的密码在服务器首次部署时随机生成，由部署者单独保管。

## 上线前准备

- 一台可以运行 Linux Docker Engine 和 Compose 插件的公网服务器，且服务器能够拉取镜像。端口 80/TCP 和 443/TCP 用于网页与 HTTPS 证书；SSH 按自己的访问来源配置。应用端口 10000 与数据库端口 5432 只供容器内部访问。 [Docker Compose 官方安装说明](https://docs.docker.com/compose/install/linux/)
- 一个可以解析到服务器的主机名。可用自有域名，也可用云服务商提供且能直接指向服务器的公网主机名。若平台已经代管 HTTPS，可用打包的应用镜像接入平台反向代理，并将演示实例连接到独立 PostgreSQL。 [Caddy 自动 HTTPS 说明](https://caddyserver.com/docs/automatic-https)
- 若选中国大陆节点，购买前向接入商核实课程网站适用的备案条件与办理时间。 [工信部《非经营性互联网信息服务备案管理办法》](https://www.miit.gov.cn/api-gateway/jpaas-web-server/front/document/file-download?fileName=82fdf880705445048aa006b2b47cb657.pdf&fileUrl=%2Fcms_files%2Ffilemanager%2F1226211233%2Fattach%2F202112%2F82fdf880705445048aa006b2b47cb657.pdf)

## 启动

将本部署目录完整上传到服务器并解压。把下面的示例主机名换为已解析的实际主机名。服务器需有 `openssl`。脚本首次生成私有 `.env`，重复运行会保留现有配置和凭据。

```sh
sh prepare-env.sh demo.example.com
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

Caddy 在主机名解析生效、80 与 443 端口可达后申请和续签证书。PostgreSQL 首次初始化创建独立的演示数据库和非超级用户，应用自行运行迁移。证书和数据库保存在命名卷中，正常重启后沿用。

## 核验老师可访问的地址

1. 从服务器以外的网络打开 `https://demo.example.com/#/home`。确认 HTTPS 有效，首页可访问，「登录」进入员工登录页面。
2. 打开 `https://demo.example.com/api/health`，确认 `ok=true`、数据库为 PostgreSQL、`demo_mode=true`。
3. 用访客窗口从登录页复制诊所经营者和医师凭据。分别确认进入各自工作台。核对昨天、今天、明天的日历，以及一条已完成样例的接诊与账单关系。
4. 手机和电脑各打开一次同一链接，确认登录、菜单、日历及登录后页面可操作。通过后把实际的 `https://…/#/home` 链接交给老师。老师可以直接从登录页取得演示凭据。

如果健康检查未通过，先查看 `docker compose ps` 及 `docker compose logs --tail=100 app db proxy`。证书错误优先核查主机名的 A/AAAA 记录、端口入站规则及是否有其他代理占用端口。应用和数据库错误通过服务器私下处理，保护配置文件及管理员凭据。

## 备份和恢复

在受限目录备份数据库，服务器启动与应用更新前保存一份。

```sh
umask 077
docker compose exec -T db pg_dump -U postgres -d adc_demo -Fc > adc-demo.dump
docker compose exec -T db pg_restore --list < adc-demo.dump > /dev/null
```

恢复时先在新的隔离数据库内用 `pg_restore --exit-on-error` 恢复并核对应用链路，再安排切换。升级前保留当前 JAR、数据库备份和文件校验值；`docker compose down` 默认保留命名卷。测试及更新期间保留这些卷。课程结束后可停止演示实例。

本目录供课程演示。如果以后承接真实诊所数据，应另选独立环境，按系统源码附带的 `DEPLOYMENT.md` 采用生产配置及机构的上线流程。
