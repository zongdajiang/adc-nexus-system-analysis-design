# ADC Nexus

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

前台、负责牙医、收费员、诊所经理、总部运营、总部财务、权限管理员和已核实绑定的患者。教师需要通过公开链接切换合成演示岗位、完整试用业务并与设计报告核对。

## Product Purpose

把牙科连锁的预约、资源、接诊、病历、治疗、结算及期间核算连成可追查的业务过程。界面必须帮助岗位完成工作，不能只展示统计或静态示例。

## Operating Context

中文为主，关键目录及数据说明保留英文。统一登录，不在登录表单选择岗位；员工编号须匹配后台名册与机构激活证据，不能仅凭编号前缀取得权限。不同岗位按服务端授权进入不同工作区。患者只查询本人已绑定资料。

## Capabilities and Constraints

现有 Java 21、JDBC PreparedStatement 与事务为实施基础，不使用 JPA。开发 SQLite，托管 PostgreSQL，同源网页随 Java 包提供。原报告 18 项核心用例及有效期、并发、同意、签署和财务状态守卫应保留。

2026-10-30 用户确认：可以补充有业务依据的功能，但必须逐项记入变更台账。仅使用合成病例；收退款为凭据登记，不执行真实支付。短信、邮箱等外部通道须有真实配置后才启用，不能用固定验证码冒充发送成功。

先完成系统与公网发布，再更新最终分析设计报告。期间冻结原 PDF，记录每项改动对应的用例、角色、API、数据、规则及验收证据。成本优先免费，不自行购买方案。免费托管的休眠和持久化条件必须如实说明。

## Brand Commitments

保留 ADC Nexus / 安德鲁牙科连锁运营管理系统的原创品牌。用户要求学习舒心牙医、Open Dental 与 DentalPin 的业务及界面优点，不复制品牌、截图、病例或受限内容。操作界面应自然、精细，减少空泛宣传、装饰性统计与生硬术语。

## Evidence on Hand

`docs/SDS.md`、原报告基线摘要、现有 Java/SQL 源码与分版本 QA。实际发布、真实通道送达与完整报告同步尚待验收；本地测试不能代替这些证据。

## Product Principles

1. 按岗位任务组织信息，让下一步操作和阻断原因可见。
2. 计划、实际治疗、签署与收费有各自身份，历史证据不覆盖。
3. UI 隐藏不代替服务端授权；每次提交重新检查范围和有效期。
4. 来源、实现和证据可追溯；目标与完成状态明确区分。

## Open Decisions

公网域名与实际云项目尚未核验。真实短信、SMTP、支付及机构医疗生产上线不在当前已验收范围。
