# 实施差异登记

| 编号 | 原报告基线 | 实施决定 | 原因 | 报告同步要求 |
|---|---|---|---|---|
| CR-001 | React/TypeScript + D1/Drizzle | Java 21 + JDBC；SQLite 本地，PostgreSQL 托管 | 用户明确优先 JDBC；免费容器本地磁盘不能保证持久化 | 架构、部署、仓储、数据库口径、技术说明 |
| CR-002 | 逐项目同意为目标；无独立物理证据表 | 新增 treatment_item_consents | 将患者决定、证明、见证人与计划项目关联 | 计划类图、临床 ERD、字典、UC-07/08 |
| CR-003 | 牙医级费用归属尚未实施 | 新增 dentist_expense_allocations | 保存财务批准的分摊依据及金额；不虚构个人奖金制度 | 费用归属类图、财务 ERD、字典、UC-12 |
| CR-004 | 病史版本尚未验收 | 新增 patient_history_versions | 追加保存患者声明与核实版本 | 患者 ERD/字典、UC-01 |
| CR-005 | 未定义跨请求幂等收据和迁移版本 | 新增技术表 request_receipts、schema_migrations | 原子重试、部署初始化可追查 | 技术设计与完整数据字典 |
| CR-006 | 正式身份通道需要机构凭据 | 保留外部通道适配边界，缺配置明确不可用 | 免费评审先使用密码与显式合成演示身份 | 实现边界及验收状态，不能标作真实短信已验收 |
| CR-007 | 病历签署字段仅在当前病历头记录 | 新增 clinical_note_signatures，关联不可变版本、签署人、牙医、时间和校验值 | 补记或新实施使当前记录待签时，仍能追查原签署 | 临床类图、ERD、字段字典与签署流程 |
| CR-008 | 收入确认及分摊制度待机构批准 | 课程验收明确选用收付实现的计算口径，核定时由财务确认 | 避免把应收、净收款与核定利润混用；不宣称机构已批准 | 财务公式、核算说明和上线条件 |
| CR-009 | 旧程序枚举为 ARRIVED/IN_TREATMENT/LOCKED 等 | 版本化迁移映射为 CHECKED_IN/IN_PROGRESS/CLOSED 等，与状态图一致 | 保持语义一致，保留历史事件与原数据源 | 状态代码清单、迁移与数据校验 |
| CR-010 | 每季度唯一激励池 | 唯一池记录指向最新核定结果；重核前后值记入审计，历史核定快照追加保存 | 遵守原唯一约束并保留重核依据 | 期间重开、快照与基金生命周期说明 |

状态：发布候选实现，已完成本地双数据库集成验收，尚未完成云端发布与最终报告同步。具体通过条目以 QA JSON 为证，不以本表代替验收。

安全收敛：多角色按具体权限隔离诊所范围；收费员只看患者身份摘要而非病史；医师限本人负责病例。季度未到期阻断关闭；重新风险复核后须重签当前病历，历史签署与后续补记理由仍保留。这些条件须进入最终报告的权限表、状态守卫和验收矩阵。

明确保留的差距：外部短信/微信通道、短信找回、临床文件新增上传、逐次服务端导出审计及真实支付尚未启用。相应设计不能删除，但必须区分目标与已验收实现。
