# 1.4 日常诊疗工作流修订

2026-10-22 · Java 21 / JDBC · 本地发布候选。此次重点不是增加装饰，而是把接待、接诊和收费拆成可处理、可交接、可追查的工作清单。新增最小化只读开单预览接口，不新增业务表，不放宽服务端权限、风险复核或财务守卫。

## 工作分区与业务语义

### 前台：门诊工作台

前台默认进入 `#/reception`。按诊所本地服务日期读取授权预约，不用历史记录填充今天的数字。提供医师、患者/预约/项目关键词筛选及待到诊、待接诊、诊疗中、已完成和取消/未到诊队列。计数覆盖所选日期；具体列表再应用医师与关键词条件。

“办理到诊”先获取该预约最新版本，再打开身份核对和变化声明表单；点击按钮本身不改变状态。已到诊由医师继续处理；已完成只表示临床阶段完成，前台不得据此声称账单已结清。牙椅未分配及未知来源状态单独提示，不自动补写数据。

### 医师：接诊队列与本次就诊

`#/clinical` 默认查看未完成记录，可切换待安全复核、待接诊、诊疗中、已完成与全部记录，按真实服务时间排序，支持患者和就诊编号检索。医师范围仍由负责关系与诊所权限决定。

`#/clinical/{id}` 分为风险核实、检查记录、方案与同意、实施项目、病历与签署五个分区。患者身份、服务日期、负责医师、诊所与已登记过敏持续显示。进入时优先显示待处理步骤，已完成记录优先打开病历；用户随后可自由切换，不强迫按界面顺序录入。

完成核查栏逐条显示 Java 服务返回的 `blockers`，而不是另写一套前端完成规则。存在阻断项时完成按钮不可用；实际提交仍由服务端事务再次核验。旧病例若按当前规则存在差距，提示复核，不自动重写历史事实。已签署版本保留；完成后补记不覆盖原文。账号签署不是第三方认证法律电子签章。

### 收费：可操作工作清单

`#/billing` 默认先显示待开单就诊；无待开单时优先显示待收款，再回退全部单据。每条待开单记录先读取最小化结算预览，列出患者、就诊、负责医师、实际项目、牙位、数量、单价快照和合计。预览不创建任何单据；勾选核对后才开单，成功后进入对应单据。新接口只读且限制财务权限和诊所范围，不返回病历正文、过敏或病史；期间锁定时仅能查看，不提供确认开单。只有实际开具单据的服务返回成功后才导航，重复开单仍按原服务幂等约束返回既有单。

有效应收合计排除作废单据；净收款由收款减退款计算；未收余额使用有效单据余额。待开单使用就诊完成时间，不冒充账单开具时间。收退款依旧登记人工核实凭据，不执行银行或支付机构资金划转。当前查询上限单据 400、待开单 300；达到上限显示提示，不能声称为无限量全网总账。

### 共同改进

顶栏“查找患者”连接实际授权档案检索；“查找功能”仍负责菜单导航，两者不混淆。只读搜索和关闭详情不再产生“已保存”提示。统一登录/退出采用单次路由绘制，减少重复刷新；不将此改动冒充所有历史登录问题的根因证明。

共享视觉采用深色窄导航、白色工作面、低饱和状态色、紧凑表格和清晰字段层级；移除指标浮图标及多余宣传式标题。患者页面、资源、核算和治理沿用相同视觉体系。首页改为文案与场景图分栏，保留三张不同图片和可暂停自动轮播。产品预览使用本地合成环境实际界面，不借用其他厂商的后台截图。

## 对照与范围

| 用例/对象 | 本轮变化 | 服务端/模型 |
|---|---|---|
| UC-01 患者资料 | 授权患者快捷查找，避免先翻功能菜单 | 原查询与收费身份摘要限制不变 |

| 身份与岗位 | 统一入口、保留不同岗位首页 | 不新增自行选角色授权；员工仍须名册与激活验证 |
