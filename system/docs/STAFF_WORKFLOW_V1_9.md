# 员工工作台业务核查版 · 1.9.0-rc1

本轮对应用户提出的收费按钮、性别年龄、只读提示和工作台操作问题。系统更新供本机验收；分析设计报告按约定保留，验收后再统一同步。本轮未发布公网服务，未增加真实支付或消息发送通道。

## 主要改动

| 工作内容 | 当前行为 | 业务约束 |
|---|---|---|
| 预约与收费交接 | 完成就诊后，分别显示核对开单、收款、查看账单或查看作废单 | 从结算接口读取对应就诊的真实单据；已结清记录不再显示收款按钮。期间未开放时仅提供查阅 |
| 单据处理 | 有待收余额且当日财务期间开放才能收款；有可退净收款才能退款；净收款为零且开单日期期间开放才能作废 | 页面条件与 Java 校验对应。每次打开收款表单重新读取单据，写入时仍检查版本、余额、期间和凭据唯一性 |
| 患者基本资料 | 档案列表显示独立的性别、年龄列；预约列表、预约详情、接诊列表、接诊页和结算单显示相同来源的人口资料 | 年龄按生日和当前业务日期计算，不持久化固定年龄。不根据姓名猜测性别，不伪造生日 |
| 患者资料修改 | 可在建档和编辑资料时设置性别；编辑后真实保存 | 校验日期及性别枚举；旧调用不传性别时保留原值。患者资料写权限保持不变 |
| 只读范围 | 无修改权限的操作列显示“只读”，查看入口保留 | “只读”不代表授予权限。已关闭期间和已取消记录用业务状态说明，不将期间关闭误称为授权失败 |
| 经营者与医师 | 经营者显示“查看接诊”；医师仅在本人负责的就诊显示接诊快捷操作 | 经营者不能代医师签署病历；服务端仍限制负责医师和诊所范围 |
| 收费工作台 | 按应收、净收款和待收金额展示同一批单据的对比图；待开单、待收款可直接进入相应清单 | 图为当前返回单据范围，不冒充全历史总额；达到查询上限时保留范围提示 |
| 期间核算 | 选择期间，查看授权诊所的净收款、成本和已核实费用；点击核算待办定位并筛选成本、费用或待分摊费用 | 经营者可查看本诊所，费用维护和期间关闭仍由总部财务办理。未完成核对时不能关闭 |
| 接诊工作区 | 保持病史、治疗、病历、签署的顺序，显示本次进度、人口资料及当前待办 | 进度取自真实保存的记录；提纲不代填诊断。更正治疗、保存草稿、签署完成各自保留实际含义 |
| 通用界面 | 统一按钮层级、间距、表格密度和中性色；保留语义状态色及键盘焦点 | 操作页面不使用装饰图片作为数据背景。宽表在自身容器内滚动，手机页面不被撑宽 |

过敏栏没有记录只表示系统中暂无相应登记，不能视作“患者无过敏”。接诊时仍需当面核实病史与过敏。原有病例、账单、密码、岗位授权、数据库结构均不重置。

## 核查范围

- SQLite、PostgreSQL：核心业务、账号、岗位边界、经营者操作、每日演示和登录密码六套回归。
- 新增 API 实测：患者性别与生日增改、输入校验、权限拦截、结清单据拒绝二次收费与作废、部分收款及退款、期间锁定、授权范围核算汇总。
- 新增界面规则实测：年龄生日边界、缺失日期、不同单据状态、不同财务期间、非负责医师、只读操作等 14 组检查。
- 浏览器：七种岗位的 49 个导航页面，桌面与 390px 窄屏；维护账号增改授权、停用与撤销授权；停诊撤销、班次停用。
- 浏览器完整流程：改期与取消、签到、病史核对、检查与治疗、误录撤销、病历草稿、签署完成、核对开单、收款；另测部分收款和原流水退款。
- 时间表：医师/牙椅分组、短时预约、重叠布局、长项目名、大字体和观察器清理。

交易测试均在独立合成数据库或业务数据的隔离副本中完成。交付版本从原本机数据库备份升级，测试病历和收退款不写入用户正在使用的数据库。验证记录对应交付 JAR 的 SHA256；不使用旧版本结果冒充当前核查。

自动检查证明列出的场景通过，不表示真实医疗生产部署或所有可能输入已被穷尽。临床判断仍由执业医师作出；本系统不生成用药或诊断建议。

## 调研依据与迁移决定

参考 Open Dental 官方 [Account Module](https://www.opendental.com/manual/account.html)、[Edit Appointment](https://www.opendental.com/manual/aptedit.html)、[Patient Dashboard](https://www.opendental.com/site/0_patientdashboard.html) 及 [Patients Report](https://www.opendental.com/manual/reportpatientraw.html)。这些资料分别强调患者收支记录、预约关联基本资料、患者上下文及按生日计算年龄。

本系统据此采用患者上下文持续可见、账单余额决定下一步、任务清单直达明细的组织方式。这些是适配本项目岗位与既有数据模型的设计决定，不是对参考软件功能范围的复制。保险理赔、家庭统账、在线真实支付等未经本项目实现与验收的能力不作展示。

## 待验收后同步

报告需同步：患者年龄展示及性别编辑；预约—就诊—结算交接条件；只读权限表达；期间汇总及待办筛选；页面操作示例和新截图。实体表结构、核心财务与临床状态机没有改动。患者微信小程序仍按独立交接合同实施，本轮不宣称小程序已发布。
