# 1.3 诊所工作流与界面修订

2026-10-21 · Java JDBC 1.3.0-rc1 · CR-014。本文区分公开产品调研、已实现功能与尚未接入的服务，不把界面展示当作医疗生产验收。

## 参考的实际产品与取舍

| 一手资料 | 观察与设计依据 | 本系统采用的方式 |
|---|---|---|
| [Open Dental：Appointments Module](https://www.opendental.com/manual/appointments.html) | 日程围绕时间、诊位、医师及预约状态组织；列表与日程承担不同任务 | 新增医师／牙椅时间表，同时保留状态看板、日列表与周列表 |
| [Open Dental：Appointment Lists](https://www.opendental.com/manual/appointmentlists.html) | 未排定、待确认和召回等工作应有独立队列，而不是混入预约状态 | 保留现有候补中心；不将本系统候补功能改称已实现的临床召回计划 |
| [Dentally：产品功能](https://www.dentally.com/en-gb/dental-software-features)、[临床功能](https://www.dentally.com/en-gb/dental-software-features/clinical)、[诊所管理](https://www.dentally.com/en-gb/dental-software-features/practice-admin) | 临床记录与行政操作分别组织，以患者和工作任务连接，而非用营销指标代替工作内容 | 首页按预约排班、接诊病历、收费报表介绍；岗位空间分别表达职责 |
| [Curve Dental](https://www.curvedental.com/) | 预约、临床、账务与经营构成关联的诊所管理范围 | 检查本系统从预约到结算的主链，不照搬海外保险、支付或地区性制度 |
| [CareStack](https://carestack.com/) | 诊所运营、患者体验、临床及收入管理均属于完整业务范围 | 用功能矩阵识别边界，不把商业产品的全部功能包装成已经实现 |
| [Bupa Dental Care：Patient portal](https://www.bupa.co.uk/dental/dental-care/patient-portal) | 患者门户处理本人资料与预约，并保留联系诊所的服务途径 | 明确当前患者入口为本人查询；自行预约、表单提交等未实现能力不作承诺 |

以上为公开产品资料的自主归纳，不复制商标、图片、源代码、病例、客户评价或经营数据。各产品受地区与机构配置影响，不能据此推定国内诊所的合规要求。舒心牙医为用户提供的视觉参考；本次使用自有排版、原创照片及已有业务模型。

## 已实现的变化

### 首页

- 三张独立照片：医患沟通、空诊室、前台接待，文件与图像散列均不同。
- 默认每 5.5 秒切换；鼠标停留及鼠标焦点不再暗中停止播放。提供显式暂停／播放、上／下一张和场景选择。
- 浏览器标签隐藏或系统设置“减少动态效果”时停止自动播放；离开首页清除计时器。手动暂停不因切换场景而失效。
- 用具体工作内容替代口号，移除首页以用例数、表数充当产品成效的展示；不虚构诊所数量、患者满意率或效率增幅。
- 保留生成图片披露，不能把合成场景当作真实客户案例。

### 预约工作区

| 功能 | 行为及边界 |
|---|---|
| 时间表 | 以诊所本地时间显示起止时段、患者、项目和状态；点击预约进入已有详情及操作流程 |
| 医师分栏 | 当前有效任职的医师形成日程列；已有历史预约即使不在当前名册仍保留显示 |
| 牙椅分栏 | 显示登记的牙椅及维护／停用状态，未分配牙椅单列，不默认为已预留资源 |
| 时间布局 | 重叠记录在独立子列显示；相接但不重叠的记录可共用子列；异常早晚时段扩展显示区间 |
| 查询 | 日期、诊所权限范围、医师、状态、姓名／预约编号／治疗项目组合筛选；显示筛选后与查询总数 |
| 日期导航 | 前一天、今天、后一天；保留日列表、周列表和状态看板 |
| 状态统计 | 待到诊、待接诊、诊疗中、已完成、未分配牙椅、取消／未到诊；明确属于当前筛选结果 |
| 取消与未到诊 | 不占用时间表；按对应状态查询时展示完整列表，原记录与理由不删除 |
| 空白时段 | 仅表示没有显示预约，**不表示可约**。创建、改期与候补确认继续经服务端检查任职、资质、排班、停诊及患者／医师／牙椅冲突 |
| 查询上限 | 沿用后端单次最多 600 条；达到上限显示提示，不能据此宣称全网周日程无遗漏 |

本轮没有新增表、没有修改原预约状态机，没有实现拖拽改期或客户端直接占位；不为追求“像商业系统”而绕开事务、版本检查、权限或审计。

## 真实场景功能核对

| 场景 | 当前可操作 | 保留的差距 |
|---|---|---|
| 接待 | 患者检索与建档、病史版本、预约、改期、取消、到诊、候补 | 未开放患者自行预约／改期，缺少通道配置时不能发送真实提醒 |
| 医师 | 本人负责就诊、风险复核、FDI 恒牙观察、方案与逐项同意、实际实施、病历签署及补记 | 非影像 PACS、非处方及药房系统；临床文件新增上传尚未启用 |
| 资源 | 有效期任职与资质、营业时间、规则班次、例外及停诊、牙椅状态、既有预约保护 | 时间表不是完整的可用性计算器；无排班拖拽和自动调班 |
| 收费 | 按实际治疗开单、整数分金额、分次收款、授权退款、原流水及打印 | 只登记核实凭据，不接支付机构或保险结算 |
| 经营 | 诊所指标、成本核实、费用归属、季度预检／关闭／重开、核定快照、扩张情景 | 无机构批准的工资发放或自动奖金划转；不能将现金口径直接替代权责发生制利润 |
| 账号 | 统一登录、角色授权、员工名册激活、本人绑定查询、OTP 逻辑与发送适配器 | 真实 SMTP／邮件及短信凭据、真实送达、云端链接与合规验收待完成 |
| 其他诊所经营 | 当前范围以分析报告 18 项用例为准 | 库存采购、消毒追溯、医保、保险索赔等未实现；应先补充需求、数据及责任边界再另立变更，不放置无效菜单 |

## 视觉规范与验证

工作区采用中性灰底、白色数据面板、统一青蓝操作色；正文与表格加大、次要信息提高对比度，减少渐变及装饰性英文口号。手机端时间表在组件内滚动，整页不应横向溢出。英文界面保留，业务枚举与金额口径不因语言改变。

自动逻辑测试见 `qa/clinic-ui-tests.json`，包含计时、暂停、隐藏与减少动态效果、区间重叠、跨日裁切、日期边界、组合筛选、不可变输入和转义。HTTP、两种数据库业务及身份验证独立执行；浏览器操作结果单列记录，不把单元测试冒充视觉验收。
