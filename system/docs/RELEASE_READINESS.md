# 发布就绪与迭代记录

本清单区分“实现了”“本地验证了”和“云端验证了”。测试通过数量不是缺陷不存在的证明；后续发现的问题仍须进入回归，不以“再无优化空间”作为不可证实的结论。

## 分轮闭环

| 轮次 | 发现或核对重点 | 实施与证据 |
|---|---|---|
| 初版 | JDBC 持久化、岗位入口与权限、预约至结算主链 | SQLite / PostgreSQL 隔离业务验收，浏览器完整主路径，备份恢复 |
| 安全与请求边界 | 异常 JSON、错误方法与来源、授权变化后的重试 | 严格 JSON 对象、错误码和请求编号；写事务内重验会话与权限，幂等签名绑定有效范围；增加回归 |
| 资源一致性 | 改星期或有效期可漏检既有预约 | 更新后核查完整规则集的覆盖，列出受影响预约并整笔回滚；核对规则指纹未被失败请求改变 |
| 交互复查 | 长弹窗底部控件越出视口，提交时可被提前关闭 | 内部滚动与固定操作栏、保存中禁用关闭、错误后恢复控件；浏览器另行确认桌面/手机布局 |
| 持续集成 | 本机结果不足以证明 Linux 构建与 PG 可用 | GitHub Actions 双数据库业务回归、请求辅助单元检查与 PG 恢复检查；结果以对应提交的运行记录为准 |
| 正式环境 | 公开链接、托管冷启动与重启持久化 | 待 Neon / Render 创建并连接后执行，不能提前打勾 |

当前本机 Java 21 打包版的业务检查：SQLite 131 项、PostgreSQL 129 项；请求辅助单元检查 6 项；隔离 PG 恢复核对 10 条数据链及 130 条有效外键。实际条目、通过状态及被测 JAR 的 SHA256 见 `qa/`。这些检查不等于压力测试、真实医疗合规或外部服务验收。

## 交付门槛

1. 阻断发布：已知越权或隐私泄漏、金额/状态错误、资源重复占用、主链中断、数据丢失、无法恢复。
2. 必须修复：阻碍教师独立完成主路径的交互问题，以及实现、说明和验收结果的矛盾。
3. 必须披露：免费冷启动、合成演示身份、外部服务未配置及其他明确保留的差距。不能用视觉包装掩盖。
4. 云端逐项核对：实际 HTTPS 地址、无本机依赖、角色差异、完整主流程、刷新及重启后数据、数据库备份与恢复方案、免费套餐和秘密不进入仓库。
5. 云端通过后更新报告：以 CR 登记为依据同步架构、67 表实施模型、状态守卫、岗位矩阵、验收、公开链接和教师操作说明；保留原始报告备份。

本地通过不代表发布已经完成。目前没有已验证的公网地址。最终报告也尚未写作“系统与报告 100% 一致”；须在报告同步后逐条核对才能给出相应证据。
