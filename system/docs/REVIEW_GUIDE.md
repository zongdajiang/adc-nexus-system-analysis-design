# 教师试用与验收路径

本系统是采用真实 JDBC 读写、持久事务和角色授权的课程合成环境，不接收真实医疗数据，不执行支付划转。公开链接以 Render 实际部署结果为准；本地地址不能代替正式链接。

## 岗位与初始工作台

| 试用身份 | 默认页面 | 可核对的差异 |
|---|---|---|
| 前台接待 | 预约与到诊 | 患者建档、预约、候补；无财务、病历签署入口 |
| 牙医 | 临床工作室 | 本人负责就诊、风险复核、病历与签署；无收款及账号管理 |
| 收费员 | 诊疗结算 | 已完成就诊开单、收退款、打印；无临床记录写入 |
| 诊所经理 | 本店运营总览 | 指标、排班和牙椅协调；不能登记收款或签署病历 |
| 总部运营 | 全网运营总览 | 任职、资质、资源、覆盖与扩张情景；无财务核定权 |
| 总部财务 | 季度核定 | 成本、费用归属、季度预检、核定及重开 |
| 患者本人 | 我的诊疗 | 仅机构核实绑定的本人预约、就诊和结算摘要 |
| 综合业务试用 | 全网总览 | 便于教师连续演练多个业务环节；这是显式合成演示角色，不是实际岗位 |

权限管理员使用私下保管的 `owner` 账号，默认只管授权与审计，不附带临床和财务权。页面隐藏之外，后端还会核验角色、有效期、诊所、负责牙医和本人绑定；手工修改 URL 不能扩大权限。

## 主路径：从预约到收款

1. 用“前台接待”建立一位合成患者，填写姓名、出生日期、电话和病史声明。重复身份会提示人工核对；未知病史不能直接当作无病史。
2. 在“安排预约”检索该患者，选择天河旗舰诊所、在该店任职且有班次的牙医（例如林玮医生）、治疗项目、当日或未来的可用时间。可先“检查当前方案”，再保存。牙椅允许暂不指定；选定后检查本店归属和占用。
3. 当日预约办理到诊，勾选身份已核对并记录资料变化。若创建了未来日期的预约，应先依法业务规则改期到当日有效时段，不允许提前伪造到诊。
4. 退出后进入“医师登录”→“牙医”。打开本人负责的就诊，完成风险复核并记录措施；开始诊疗。
5. 在 FDI 牙位图记录观察。新增治疗计划，记录患者对具体项目的接受、拒绝或暂缓及依据。计划不会直接产生收费。
6. 如实登记实际治疗、牙位及数量。无计划的实际治疗允许留存事实，但完成前须补充适当计划与患者同意，用“补全项目关联”记录更正原因；这不会覆盖实际治疗金额和时间。
7. 保存并签署本版本病历。后续新增观察、风险复核或实施会使当前病历待重新核对签署，历史签署证据仍保留。核对完成条件后，完成就诊；预约同时变为已完成。
8. 用“收费员”进入结算，从未开单的已完成就诊生成逐项结算单。计划项目不会被收费；金额取实际治疗的价格快照。
9. 可分次登记经核实的收款凭据。超收、重复凭据、超额退款会拒绝。退款关联原收款，结清状态按净收款重新判定，原流水不会被覆盖。可打印本次结算凭证。

## 分支与例外

- 预约：改期须重新验证资源；已到诊或已有临床事实不能直接取消；未到诊须超过结束时间及 15 分钟宽限。
- 候补：先登记患者可接受的日期、诊所及通知时限，再选择已取消的未来时段邀约。确认窗口为 15 分钟，患者明确接受后重验资源并建立预约。
- 资源：经理尝试将仍有有效预约的牙椅设为维护，或新增影响预约的停诊，应收到协调提示，不能直接破坏既有安排。
- 病历：完成后的补记必须说明理由，追加新版本并保留原签署；签署留痕不是第三方法律电子签章。
- 季度：总部财务核实实际成本及运营费用，批准费用归属，核对诊所、牙医贡献和全网结果。未到期、未核实或未完整分摊时不能关闭。基金按全网正净利润的 10% 计算，不虚构个人奖金分配制度。
- 绩效：同时查看日期、分子、分母与口径说明；历史牙椅容量以当前配置估算，不能冒充已批准的历史考核。
- 扩张：保存候选条件、需求和成本假设，计算情景结果；结果不会自动增加真实诊所或创造已确认资质覆盖。

## 未启用或仍待验收

短信/微信通道及短信找回密码需要机构凭据；目前明确提示未配置。当前没有新增临床文件上传功能，不把种子数据中的附件元信息算成可用上传。尚未执行真实支付、机构实名核验、第三方电子签名、生产医疗合规及压力容量验收。

公共试用身份共享一套合成数据，别人的试用可能改变看板；以实际数据库记录和审计为准。不要用真实姓名、电话、病史或付款资料测试。云端持久化重启、冷启动和实际公开链接的检查须在正式部署后另行记录。
