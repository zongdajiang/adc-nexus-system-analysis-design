# 浏览器验收记录 · 2026-10-21

范围：本机 Java 21 打包 JAR、SQLite JDBC 合成数据库；非托管环境。

已实际通过界面操作：前台患者检索 → 限定诊所牙医/牙椅 → 方案校验 → 保存预约 → 身份确认到诊 → 医师复核两项既往过敏 → 开始诊疗 → FDI 16 观察 → 计划及逐项接受依据 → 实施价格快照 → 病历版本签署 → 就诊完成 → 收费员从完成就诊开单 → 合成收款 → 刷新后结清余额保留 → 患者本人门户显示同一就诊与账单。

确认前台、医师、收费员、患者入口分别进入对应工作区；患者导航仅本人诊疗和账号安全。收费员没有临床签署或授权治理入口。API 越权防护由集成测试另行覆盖。

发现并修复：有过敏患者的复核写入缺少非空英文字段；初始演示预约默认状态与历史不一致；患者范围标签错误；刷新深链接丢失；脚本缓存更新；手机表格挤压。相关后端情况已补充自动回归。

手机视口：390×844，正文可视宽度 375（扣除滚动条）与文档宽度一致，无页面级横向溢出；宽表在内部横向滚动，最小宽度 640。检查后已恢复默认桌面尺寸。截图在本地 `qa/browser/`；公开展示精选图放在 `docs/images/`。

限制：没有把少量截图当作全部页面无缺陷的证明；未验证真实短信、微信、支付划转、机构实名、医疗合规或云端可用性。
